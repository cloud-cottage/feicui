## 2. 字表纪律（**唯一实现**＝`ocr_corrector.validate_map`，自检里有 3 条判负用例）

- 每条必带 `from` / `to`（**单字**，保证 `pos` 级可追溯）/ `source` / `confidence` / `verified` / `note`。
- `source` 白名单与置信区间（**不得自造来源标签、不得越界**）：

| source | 含义 | confidence 上限 | 可 `verified=true`？ |
|---|---|---|---|
| `measured_truth` | **有真值的实测**（OCR 输出 vs 人工核定正确释文） | 1.0 | ✅ **唯一允许** |
| `corpus_stats` | 从 `stamps.text` 统计出的事实（「哪些字高频」） | 0.6 | ❌ |
| `cross_engine` | 两引擎同图输出不一致（观测事实，谁对未知） | 0.6 | ❌ |
| `font_glyph_shape` | 本地字体栅格字形相似度（楷/黑体代理，非篆书） | 0.5 | ❌ |
| `inferred` | 待审候选，无上述证据 | 0.4 | ❌ |

- 同 `from` 两条规则 ⇒ 校验失败（命中歧义）。
- 现表（v0.3.0-draft，2026-10-16 人工裁定后）：**52 条 = 2 条 `measured_truth`（verified） + 50 条候选（全部 verified=false）**。
  两条 verified 条目＝`gx-0001 錄→鈢`（Kevin 样本实测，两引擎一致误读）与
  `gx-cand-0027 鲜→鮮`（**人工核验**判对，非 OCR 实测样本 —— `evidence.kind=human_adjudication`）。
- 顶层另有 `policy`（推荐级：`font_glyph_shape`/`cross_engine` 一律 `evidence_only`）与
  `rejected[]`（人工裁定判错的条目原样存证，**不参与纠错**，且 `merge_map_entries.py` 不会把它合回）。
  详见 §0。

## 8. 风险与坑（实现时踩到/需人知晓）

- **候选排序会被「跨引擎一致次数」主导**：`團→图` 之所以排第 1，是因为 Paddle 在同枚上真的报了
  `图`；但两引擎**同错**是常态（「左軍丞錄」就是两引擎一致误读）⇒ 跨引擎一致**不等于**正确。
- **字形代理的字体是黑体**：`錄↔鈢` 0.5128 是**黑体**下的读数；篆书下的真形状关系未知
  ⇒ 分数只用于排序，不用于打标。
- **语料里 41% 是数字/拉丁噪声**（秦印类编的著录号、福庵印缀的编号）⇒ 任何「用字统计」必须先过滤。
- **`stamps.text` 无古玺汇编行（0）**：拿它当古玺用字表是**代理**，会有系统性偏差。
- **`suggest` 的 `hits` 会把「候选」也算成命中**：`stats.hit_by_source` 分开计数，
  报告里「触发率」必须注明是「任一规则命中」还是「verified 命中」，否则会被读成准确率。
- 字表 JSON 的 `from` 唯一性是硬校验：**同一误读字只能有一条规则**（多个候选要放进
  `evidence.alternatives`，不要拆成多条同 `from` 规则）。
- ★ **字形代理分已被人工抽检证伪**（§0）：不得再以「分高」为由把 `font_glyph_shape` 候选提为推荐；
  本轮反例＝全表最高分 0.7454 的 `干→千`（判错）。§4 的「种子标定」只说明「排序启发式在**唯一有真值**的
  那个字对上站得住」，**不能**外推成「排序 = 正确」。
- ★ **裁定判错的条目会被脚本复活**：`merge_map_entries.py` 按「同 `from` 不覆盖」去重，删过的 `from`
  在下一次 `--apply` 时会**被重新合入** —— 本单已修：脚本会跳过字表顶层 `rejected[]` 里的条目
  （并在终端打印跳过清单）。改 `rejected[]` 前请先改 `notes`/`policy`，别只删数组项。
- ★ **别让脚本回退人工审核状态**：旧版 `merge_map_entries.py` 会把 `version/updated_at/review_status`
  写死成 `0.2.0-draft`/`unreviewed`，跑一次就会抹掉「部分已审 + 审核人」的留痕 —— 本单已改为**保留现值**。

## 9. 字表数据源接入点（**将来由 xiai 在线 API 提供** —— 本单只留可替换接口，**不实现**网络拉取）

Kevin 定的将来形态：映射数据由 **xiai 项目**的在线 API 提供，feicui 只做消费方。
本单**不实现网络拉取**（该 API 尚不存在、本线无联网许可），本地
`webui/data/guxi_variant_map.json` 为**离线回落**。

- **接口约定（xiai 侧要按这个实现）**：`GET <base>/guxi-variant-map` → JSON，**与本地 schema 兼容**
  （`guxi_variant_map/v1`）：

  ```json
  {"schema": "guxi_variant_map/v1",
   "version": "<语义版本>",
   "updated_at": "YYYY-MM-DD",
   "entries": [{"from": "錄", "to": "鈢", "source": "measured_truth",
                "confidence": 0.9, "verified": true, "note": "…"}]}
  ```

  建议**带 `version`**（比对用）并支持 `ETag` / `If-None-Match`（304 免重传，供缓存）；
  `entries[]` 的字段与本地一字不差（`from/to/source/confidence/verified/note`，可带 `rule_id/scope/evidence/context`）。
- **feicui 侧接入点（已就位，换源不需要改纠错层）**：
  `ocr_corrector.load_map(path)` 读本地 JSON；`ocr_corrector.correct(text, map_data=<dict>)`
  接受**任何来源**产出的同 schema dict ⇒ 将来的拉取器只要产出 dict（或把响应缓存成临时文件后传
  `map_path`）即可，`ocr_corrector` / `--selftest` / `eval_corrector.py` / `make_review_table.py` 都不用动。
- **纪律（将来的拉取器必须同样遵守）**：
  ① 响应**必须**过 `validate_map`（非法 source / 越界 confidence / 假 `verified=true` 一律拒用，
  **宁可回落本地 JSON 也不放宽校验**）；② 只有 `verified=true` 且 `source='measured_truth'` 的条目能参与
  `mode='auto'`，远程数据**同样不得**把 `font_glyph_shape`/`cross_engine` 候选当推荐（§0）；
  ③ 拉取失败 / 超时 / 校验不过 ⇒ **回落本地 JSON**，并在界面上标注所用 `version`（避免「离线旧表」与
  「在线新表」被混读）；④ **不新增依赖**（stdlib `urllib.request` 足够，不引入 requests）。
- **本单未做（明确未实现）**：网络拉取、缓存目录、ETag 存储、UI 版本标注、鉴权 —— 全部未做。
