## 1. 需求

**Kevin 原话（逐字照登）**：

> 「新增一个功能，输出的时候要保留原始切片，格式依旧是 TIFF，但是命名需要形如 `P40-C1-R1-O.tiff`，字母 O 代表是原始切片。」

**释义（Zang 拆解）**：每枚印面在**已有的颜色校正件**之外，**另出一份「原始切片」**——即从 PDF 渲染后按库内 `bbox` 裁出的**未做颜色处理**的原片；格式仍为 TIFF；命名在既有的 `P<页>-C<列>-R<行>` 之后**追加 `-O`**。

**Kevin 追加两答（同日）**：① **旧件全部回填**（范围＝全部已解析行，非仅新 job）；② **O 件用 TIFF 编码**。

## 2. 默认口径（不答即按此执行；均「一句话可改」）

| 项 | 口径 |
|---|---|
| **O 的定义** | **原始裁片**＝`processor.render_page`（400 dpi）渲染后按 `stamps.x1..y2` **原样裁出**，**不做任何颜色处理**（不跑 V3、不改纸色、不动色度） |
| **几何** | 与同页同 `(C,R)` 的校正件**完全一致**（同 bbox、同渲染倍率、同尺寸） |
| **容器** | **TIFF · RGB 8-bit · Deflate ＋ `Predictor=2`**。**2026-10-11 实测裁决**：deflate+Predictor 均 **289.7 KB** vs deflate 均 391.9 KB ＝ **73.9%（省 26.1%）**，且**解码像素与原片逐像素相等**；`lzw` 反而 137.5%、`adobe_deflate` 等同 deflate ⇒ 都不用。**不得** JPEG-in-TIFF、不得 webp。**校正件的编码与字节不动。** |
| **命名** | `P<页>-C<列>-R<行>-O.tiff`（大写 O、短横分隔、不补零；例 `P40-C1-R1-O.tiff`） |
| **落点** | 与校正件**同目录**：`output/books/<书籍目录键>/` |
| **范围** | **印谱解析线全部已解析行**（当前 **8708 行**：秦印类编 7183 / 福庵 1214 / 秦汉印典 35 / tmp.pdf 31 / 古玺汇编 23 / 黄牧甫 200 / 吴颐人 22）；**印章线不纳入**（其命名面 R58 未裁） |
| **落库** | **不新增列**：O 路径由命名规则**派生**（校正件路径把 `.tiff` 换成 `-O.tiff`）；`stamps.img_path_tiff` 仍 = **校正件** |
| **幂等** | 已存在且**解码像素一致**则跳过（**判据按解码像素、不得按文件 sha256**——Pillow `tiff_deflate` 在大图上逐字节非确定）；**O 件容器口径变化（如启用 `Predictor`）时按「像素＋容器」判、自动升级重写** |
| **失败** | 逐条入清单，**不得静默跳过** |
| **红线** | 只增文件、**校正件字节不得变**、不改 `stamps` 既有列值、不新增列、不建 job、不碰印章线、不碰 `output/faces/**`（已空） |

### 3.3 体积口径（诚实登记）

- 三批样本均值差 **3 倍**（47 枚小样本 124 KB/枚 ｜ 213 枚子集 ≈174 KB/枚 ｜ 24 件实产 O 件 392 KB/枚）⇒ **裁片尺寸分布差异极大**（福庵重扫描件的大印面是主因）。
- **全量 8708 枚的总体积以回填单实测为准**；启用 `Predictor=2` 后按子集（≈174 KB ⇒ ≈129 KB/枚）外推 ≈ **1.1 GB**，按 24 件样本（392 KB ⇒ 290 KB/枚）外推 ≈ **2.4 GB** —— **两值均不作结论**。

## 4. 验收候选（底稿，供 Jing 入册；对应 AC-110〜AC-114）

- **O-1 命名**：存在性——每个 `P<页>-C<列>-R<行>.tiff` 必有同目录 `P<页>-C<列>-R<行>-O.tiff`；命名逐行合 `^P[0-9]+-C[0-9]+-R[0-9]+-O\.tiff$`、无补零。
- **O-2 原始性（最强判据；2026-10-11 按实测修正）**：O 件**解码像素 ≡** 同页同 bbox 的 400 dpi 渲染原片（逐像素相等，**所有行**）；**「O ≠ 校正件」只在 V3 生效的行成立**——V3 `skipped(ink_ratio<2%)` 的行里 V3 是 no-op，其校正件本就等于原片 ⇒ **O == 校正件合法**。
  **判决式**：`eq_render == 行数` **且** `「O ≠ 校正件」的计数 == V3-applied 的行数`。
  实测依据：子集 213 行中 V3-applied **197** 行；另 16 条 `o2_o_equals_corrected` 全部落在 V3-skipped 面（秦汉印典 p5 / tmp.pdf 等低印红页）⇒ **非缺陷**。
- **O-3 几何一致**：O 与校正件尺寸（宽×高）逐行相等。
- **O-4 容器**：`mode=RGB`、`Photometric=2`、`Compression=8`（Deflate）、**`Predictor=2`**、**非** JPEG-in-TIFF。
- **O-5 双向对账**：库行数 × 2 = 盘上两类文件数（无孤儿、无缺失，给两个方向计数）。
