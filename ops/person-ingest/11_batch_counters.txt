# 证据⑪ 批次行计数修复：关联不得被幂等重放归零   2026-10-10T08:02:59+08:00

## 问题
person_import_batches 行的 fetched/relations_ok/elapsed_s 被**最后一次幂等重放（skipped_resume=570）**的读数覆盖，以致 API 与 UI 把「0」当成「未采集/无关联」（真值 relations=1650）。

## 根因
旧 run_sync 把本 run 的循环计数（重放时全为 0）直接写入批次行；create_batch 用 INSERT OR REPLACE 每次重跑都把计数清零；persons_ok/relations_ok 亦取自本 run 计数而非库内真值。

## 修改点
  * persons_ok/relations_ok: 改为库内对该批次的**实测计数** batch_db_counts(batch_id)（COUNT(*) WHERE batch_id=?），不写死；
  * fetched/elapsed_s: 改为**采集 run 累计**并跨 run 保留；幂等重放（fetched==0 且全部 skipped）不改写采集计数；
  * create_batch: INSERT OR REPLACE → INSERT ... ON CONFLICT DO UPDATE（重跑只刷 updated_at/status/source_total/params_json），绝不归零；
  * new fields: ['last_run_kind', 'last_run_fetched', 'last_run_skipped', 'last_run_elapsed_s', 'last_run_at']
  * legacy_repair: repair_batch_counters()：受损行（计数≠库内真值）persons/relations 取库内实测，fetched/elapsed 取该批次包 report.json → run_provenance.acquisition_run（采集期记录），原重放读数移至 last_run_*。
