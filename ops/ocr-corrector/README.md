## 1. 交付物

| 文件 | 作用 |
|---|---|

## 2. 字表纪律（**唯一实现**＝`ocr_corrector.validate_map`，自检里有 3 条判负用例）

- 每条必带 `from` / `to`（**单字**，保证 `pos` 级可追溯）/ `source` / `confidence` / `verified` / `note`。
- `source` 白名单与置信区间（**不得自造来源标签、不得越界**）：

| source | 含义 | confidence 上限 | 可 `verified=true`？ |
|---|---|---|---|
| `measured_truth` | **有真值的实测**（OCR 输出 vs 人工核定正确释文） | 1.0 | ✅ **唯一允许** |
| `corpus_stats` | 从 `stamps.text` 统计出的事实（「哪些字高频」） | 0.6 | ❌ |
| `cross_engine` | 两引擎同图输出不一致（观测事实，谁对未知） | 0.6 | ❌ |
| `font_glyph_shape` | 本地字体栅格字形相似度（楷/黑体代理，非篆书） | 0.5 | ❌ |
| `inferred` | 待审候选，无上述证据 | 0.4 | ❌ |

- 同 `from` 两条规则 ⇒ 校验失败（命中歧义）。
- 现表：**55 条 = 1 条 `measured_truth`（verified） + 54 条候选（全部 verified=false）**。
  唯一 verified 条目＝`gx-0001 錄→鈢`（出处见字表 `note`/`evidence`：Kevin 样本实测，两引擎一致误读）。

- **格式**：每枚一张印面图 + 一行**正确释文**（汉字串，无标点/空格/朝代/页码）。

## 8. 风险与坑（实现时踩到/需人知晓）

- **候选排序会被「跨引擎一致次数」主导**：`團→图` 之所以排第 1，是因为 Paddle 在同枚上真的报了
  `图`；但两引擎**同错**是常态（「左軍丞錄」就是两引擎一致误读）⇒ 跨引擎一致**不等于**正确。
- **字形代理的字体是黑体**：`錄↔鈢` 0.5128 是**黑体**下的读数；篆书下的真形状关系未知
  ⇒ 分数只用于排序，不用于打标。
- **语料里 41% 是数字/拉丁噪声**（秦印类编的著录号、福庵印缀的编号）⇒ 任何「用字统计」必须先过滤。
- **`stamps.text` 无古玺汇编行（0）**：拿它当古玺用字表是**代理**，会有系统性偏差。
- **`suggest` 的 `hits` 会把「候选」也算成命中**：`stats.hit_by_source` 分开计数，
  报告里「触发率」必须注明是「任一规则命中」还是「verified 命中」，否则会被读成准确率。
- 字表 JSON 的 `from` 唯一性是硬校验：**同一误读字只能有一条规则**（多个候选要放进
  `evidence.alternatives`，不要拆成多条同 `from` 规则）。
